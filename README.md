# Green Spice

Green Spice is a user-friendly app for one restaurant that brings delivery,
takeaway, and dine-in ordering together with tools for the restaurant team to
manage service and operations.

The app includes customer ordering and account screens, admin dashboards and
branch management, and separate floor and operations experiences for managers.
The client is built with Expo SDK 58, React Native, TypeScript, and Expo Router.

## Local development

1. Install the project dependencies:

   ```sh
   npm ci
   ```

2. Set `EXPO_PUBLIC_API_URL` in your local environment to the backend server
   origin. Do not commit credentials or secret values.
3. Start the app:

   ```sh
   npm start
   ```

   This starts Expo in Expo Go mode. See [Running on Android](#running-on-android)
   for features that need a native app build.

Other project commands:

```sh
npm run web
npm run android
npm run ios
npm run lint
```

# Google Maps build configuration

The customer address and admin store-detail maps use `react-native-maps`.
Android builds require a Google Maps Platform API key with **Maps SDK for
Android** enabled. Configure `GOOGLE_MAPS_ANDROID_API_KEY` in the build
environment; do not commit the key.

The key is passed to the native Maps SDK by `app.config.js`. For EAS, create a
**Sensitive** `GOOGLE_MAPS_ANDROID_API_KEY` variable in the environment used by
the build profile: `preview` for APK builds and `production` for production
builds. The `.easignore` file also includes the local `.env` for EAS prebuilds,
while `.gitignore` keeps it out of Git. Restrict the key to the Android package
`com.ggst.greenspice` and the SHA-1 fingerprints for the build certificates.
Android EAS builds fail early if this key is missing. Expo Go uses its bundled
map configuration; other Android builds show a fallback instead of crashing
when the key is not configured.

A Google OAuth client ID is not a Maps SDK key and is not used by this map.
iOS uses Apple Maps by default. To use Google Maps on iOS as well, configure
`GOOGLE_MAPS_IOS_API_KEY` with **Maps SDK for iOS** enabled and restricted to
the bundle identifier `com.ggst.greenspice`. If this key is absent, iOS keeps
using Apple Maps.

# Running on Android

Run `npm start` to start Metro in Expo Go mode and scan its QR code with Expo
Go. Voice search uses a native speech-recognition module that Expo Go does not
include, so voice search is unavailable when running the app in Expo Go. Use an
Android or iOS build that includes the native speech-recognition module for
voice search. Expo Go also limits Android media-library access, so saving table
QR codes from the manager screen requires an installed app build for full
functionality.

# Android release builds

The Android release build enables R8 code shrinking/obfuscation and resource
shrinking. This can reduce the app's DEX and resource size; the final AAB size
depends on its dependencies and the device-specific downloads generated by
Google Play.

The `android` directory is generated and is not committed to Git. After pulling
changes to `app.json` or `app.config.js`, run these commands from the project
root to generate/update the native project and install dependencies:

```powershell
npm ci
npx expo prebuild --platform android
```

Then build a release APK from the `android` directory:

```powershell
cd android
.\gradlew clean
.\gradlew assembleRelease
```

The APK is at
`android/app/build/outputs/apk/release/app-release.apk`.

For a Play Store AAB, run either command from the project root:

```powershell
npx react-native build-android --mode=release
```

or, from the `android` directory:

```powershell
.\gradlew bundleRelease
```

Both AAB commands build the Gradle `bundleRelease` task. The AAB is at
`android/app/build/outputs/bundle/release/app-release.aab`. Your commands were
therefore correct for producing an APK and AAB; the important extra step is
running Expo prebuild after pulling the config changes so the generated Gradle
project has R8 enabled.

Both local release builds generate the matching R8 mapping file at
`android/app/build/outputs/mapping/release/mapping.txt`. Keep a copy of that
file for every release and upload it in Google Play Console with the
corresponding AAB. Do not reuse a mapping file from a different build. The
`buildArtifactPaths` setting in `eas.json` collects this file only for EAS
Builds; it does not collect artifacts from local Gradle builds.

Make sure the release variant is signed with the same Play upload key used for
your app updates. Do not upload a release built with a debug signing key.
